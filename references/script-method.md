# 口播脚本方法论

写给「工业数字化 / 售前」这类技术讲解号。目标不是文学性，是**看完 + 记住 + 认人**。

## 一、先定三件事，缺一不动笔

| 问题 | 为什么必须先答 |
|---|---|
| **讲给谁** | 同行、客户决策人、泛技术爱好者，三种人钩子完全不同 |
| **时长** | 决定结构，也决定图元预算（见下） |
| **要对方记住哪一句话** | 一条片子只能有**一个**核心结论，多于一个等于没有 |

## 二、结构（45–90 秒最优）

```
0–5s    钩子      反常识 / 数字 / 痛点，一句话把人钉住
5–15s   冲突      大家通常怎么理解 → 为什么不对
15–70s  拆解      2–4 个信息点，每点配一张手绘画面
70–90s  结论      回到那一句话，加一个可执行的落点
```

**抖音技术区 45–90 秒完播率最稳。** 超 120 秒必须靠连续钩子（每 15 秒一个小转折）撑，否则划走。

## 三、钩子四式

| 型 | 例 |
|---|---|
| 反常识 | 「网关不是转发器。这个误会害了很多项目。」 |
| 数字 | 「73% 的工业数据采上来之后，从没被人看过。」 |
| 痛点 | 「你是不是也遇到过，PLC 一断线，整个平台就瞎了。」 |
| 直接给结论 | 「记住一句：网关永远不要直连数据库。」 |

钩子画面用**模板 C（大数字）**或**单行大字**，3 秒内必须出现内容，不要空镜。

## 四、一镜一信息点

**一条镜 = 一个信息点 = 3–8 秒旁白 = 3–5 个图元。**

反例（一条镜塞两个信息点）：

> 「网关要做协议转换，同时还要做单向隔离，这样即使生产网被攻击也波及不到平台。」

这句话里有「协议转换」和「单向隔离」两个可以各画一张图的点，硬塞进一条镜的结果是
图元预算超载、画面「唰唰唰」闪过。

正解 —— 拆两镜：

```
镜 1：「网关要做的第一件事，是协议转换。」        → 画：PLC → 网关 → 平台
镜 2：「第二件事，单向隔离。数据只能往上走。」    → 画：两条带方向的箭头，一条打叉
```

## 五、术语必须试听（最容易翻车的地方）

TTS 对缩写和数字的读法不可预知，**必须逐条试听**：

| 风险 | 处理 |
|---|---|
| `PLC` `MCP` `OPC UA` | 可能读成字母串、也可能整词读。试听后决定是否改写成「可编程控制器」 |
| 百分号 / 小数 | `73%` 可能读成「七十三百分号」。写成「百分之七十三」更稳 |
| 型号 / 版本号 | `S7-1200` 读法必错，改写或拆开 |
| 多音字 | 「重」量 / 重「要」、「行」业 / 银「行」 |

**画面里可以写缩写，旁白里要写读起来对的写法。** 这也是本方案的优势 ——
画面文字是文本层，与旁白文本可以不一致。

## 六、命名与个人 IP

技术 IP 的辨识度来自**稳定的形式**，不是每期换花样：

- 固定开场句式（每期同一句结构的话）
- 固定的视觉：同一种纸底、同一支「笔」、标题永远在左上、下划线永远蓝色
- 固定的一句话收尾

本技能默认的视觉（暖白纸底 + 行楷 + 蓝色下划线）就是为这个准备的。
**不要每期改色改字体** —— 那是在消耗辨识度。

## 七、选题（比制作更决定成败）

能做的三类，按成功率排：

1. **避坑** —— 「XX 千万不要这样接」。有对立面，天然有钩子
2. **对比** —— 「A 和 B 到底差在哪」。适合用模板 B
3. **原理拆解** —— 「XX 到底怎么工作的」。信息密度高，涨粉慢但粉丝质量好

不要做的：

- **新闻转述** —— 没有差异化，你转别人也转
- **工具教程** —— 版本一换就废，且竞争最激烈
- **纯概念科普** —— 泛而不深，抓不住精准客户

对你（售前）特别值的一条：**把客户现场被问倒的问题，做成一条视频。**
这类选题自带真实感，且能直接当销售素材复用。
