# shot.json 契约

一个镜头 = 一个 JSON。流水线读它、配音、算时间轴、渲染。

## 顶层字段

| 字段 | 默认 | 说明 |
|---|---|---|
| `title` | — | 镜头名，仅用于工程标识 |
| `size` | `[1080,1920]` | 竖版抖音规格，一般不改 |
| `fps` | `30` | 帧率 |
| `seed` | `11` | 手绘抖动种子。**同一个 seed 抖动完全可复现**；换 seed 会给同一版式一套新的手抖纹理 |
| `theme` | `ink` | 配色主题 |
| `font` | 自动 | 指定字体路径；默认按「行楷 → 华文楷体 → 楷体 → 雅黑」优先取本机第一个可用 |
| `voice` | — | 音色全名或别名（见 voice.py 的 VOICES） |
| `voice_text` | — | 本镜旁白原文。目录模式下用 `voice.py` 单独合成 |
| `elements` | `[]` | 图元列表，**数组顺序 = 绘制顺序** |

## 图元类型

所有图元通用字段：`type`、`x`、`y`、`cue`、`delay`（额外延后秒数）、
`color`（`[r,g,b]`）、`font`（字体覆盖，见下）、`jitter`（抖动幅度，默认 1.15）。

**`font` —— 元素级字体覆盖。** 默认全片用行楷（手写感），但行楷写拉丁缩写会偏手写体，
实测 `AI` 会被认成 `A7`。凡是**主题词、技术术语、型号、数字**所在的元素，
都该单独给一个：

```json
{"type": "title", "text": "AI Agent", "x": 92, "y": 230, "size": 92, "font": "sans"}
```

| 值 | 效果 |
|---|---|
| `"sans"` | 黑体（simhei），术语与缩写首选 |
| `"hei"` | 更粗的雅黑，用于超大数字 |
| `"kai"` | 行楷 / 楷体，强制回到手写体 |
| 绝对路径 | 任意字体，如 `"C:/Windows/Fonts/simhei.ttf"` |

留空即用镜头默认字体。**是改单个元素，不是改整镜** —— 全片换字体等于丢掉辨识度。

| type | 专属字段 | 说明 |
|---|---|---|
| `title` | `text` `size` `align` `text_width` | 大字标题。会自动在下方加一道手绘下划线。<br>`text_width` 给下划线长度，不给则按字数估算（中文字宽≈字号×0.98） |
| `text` | `text` `size` `align` | 正文文字 |
| `box` | `text` `w` `h` `r` `size` `text_size` | 圆角框，一笔顺时针画完。文字在框内居中，等框画完再写 |
| `arrow` | `x2` `y2` `head` `head_angle` | 从 (x,y) 到 (x2,y2)，笔画完后续画箭头 |
| `line` | `x2` `y2` `dash` `gap` `label` | 直线。给 `dash` 变虚线（表示距离 / 相似度这类非实体的关系）；`label` 在中点上方落一个标签 |
| `group` | `w` `h` `r` `text` `dash` `gap` `text_size` | 虚线分组框，逐段画。`text` 是左上角标签，画在框外上方 |
| `dot` | `r` `text` `label_pos` `text_size` | 一个手画圆点 + 标签。`label_pos` 取 `below`（默认）/ `above` / `right` |
| `scatter` | `w` `h` `points` `groups` `axes` `point_r` `stagger` | 散点图 / 向量空间。**整张图算一个图元**，内部点按 `stagger` 依次亮起。<br>`points[]` 每项 `{dx, dy, text?, r?, color?, text_dy?}`，`dx/dy` 是 **0..1 归一化**坐标；`groups[]` 是组标签 |
| `cylinder` | `w` `h` `cap` `text` `label_dy` | 数据库圆柱。顶面椭圆 + 侧壁一笔连画。`cap` 控制顶面椭圆扁度（默认 0.17） |
| `bars` | `w` `h` `values` `bar_ratio` `axis` `text` | 一排竖条，表示「一串数字」= 向量的分量。高度取 `values` 绝对值归一化 |

> **绘制作图（scatter / cylinder / bars）笔画多、单元素耗时长。** 如果它落在很短的一镜里，
> 给它加 `"dur_scale": 0.7` 整体提速，比砍内容划算。

> **文字也能逐笔。** 所有文字默认 `per_char: true` —— 逐字浮现，模拟书写。
> 底层字体是行楷 / 楷体，不是印刷黑体，所以「写」的观感成立。

## cue：声画同步的开关

`cue` 是一个**词**。引擎拿它去配音的净文本里找第一次被念到的时刻，
那一刻就是该图元开始画的时刻（再提前 `lead` 秒，默认 0.14s）。

```json
{"type": "box", "text": "网关", "cue": "隔离", "x": 330, "y": 960, "w": 420, "h": 170}
```

三条硬规则，违反任何一条都会让同步失效：

1. **cue 词必须真实出现在 `voice_text` 里。** 匹配前会去掉标点和空白，
   所以「隔离」能匹配到「……是隔离和汇聚」里的「隔离」，但配音里没说过「PLC」就永远匹配不上。
2. **图元的绘制顺序必须与 cue 在语音中的先后顺序一致。**
   `elements` 数组按从上到下、从左到右排；引擎按数组顺序前进查找。
   如果第 3 个图元的 cue 在语音里比第 2 个还早，第 2 个会被顺延 —— 同步就废了。
3. **不必每个图元都给 cue。** 一条镜里给 2–4 个关键节点打 cue 就够，
   其余图元省掉 `cue`，会自动顺排在前一个之后（错开 0.35s）。

## 密度：最容易踩的坑

**绘制比语音慢得多。** 实测基准（`DRAW_SPEED = 780 px/s`）：

- 一个 320×140 的框 ≈ 1.2 秒画完
- 一条 130px 的箭头 ≈ 0.2 秒
- 一行 4 字标题 ≈ 0.9 秒（含下划线）
- 一行 6 字正文 ≈ 0.75 秒

而一条 8 秒的配音，人一口气能说完 5–6 个信息点。
**两边节奏天然不匹配** —— 说完了但还没画完。

经验换算：

| 配音时长 | 图元上限 |
|---|---|
| 5 秒 | 3 个 |
| 8 秒 | 4–5 个 |
| 15 秒 | 7–8 个 |
| 30 秒 | 12–15 个（建议拆成 2–3 镜） |

`timeline.py` 会体检并在超载时打印告警：

```
[注意] 本镜 7 个图元需要 9.4s 才能画完，而配音只有 6.8s。建议拆成多镜，或把图元减到 6 个以内。
```

**看到告警就减图元或拆镜，别硬跑** —— 硬跑的后果是每个图元被压到 0.55s 以内
「唰」地闪出来，完全没有手绘感。

## 画布安全区

```
y = 0     ┌──────────────────────┐
          │ 上留白 120            │
y = 120   │   ┌──────────────┐   │
          │   │  内容区       │   │  左右各留 72
          │   │              │   │
y = 1536  │   └──────────────┘   │
          │ 字幕安全区（20%）     │  ← 不要在这里放任何图元
y = 1920  └──────────────────────┘
```

抖音的底部 UI（点赞、评论、作者信息）会盖住最下面约 20%。
字幕由流水线末尾统一烧在 `y ≈ 1536` 的位置，图元不要越过这条线。

单屏图元数建议 ≤ 5 —— 竖版视野窄，挤多了必糊。

## 颜色

| 用途 | 值 |
|---|---|
| 纸底 | `[250,247,242]` 暖白 |
| 主线 | `[32,32,34]` 墨黑 |
| 主色 | `[13,72,206]` `#0D48CE` 蓝 —— 用于标题下划线、重点框 |
| 次要 | `[122,130,146]` 灰 —— 分组框、辅助标注 |
| 强调 | `[176,58,48]` —— 仅用于「坑/警告」类内容 |

整体走蓝色系，多彩只作为备选。给某个图元单独上色用 `"color": [r,g,b]`。
