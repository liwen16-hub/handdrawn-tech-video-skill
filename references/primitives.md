# 版式与图元画法

坐标是 1080×1920 的逻辑像素，**所有 y 值不要超过 1500**（下面留给字幕和平台 UI）。

## 画布分区

```
x:  0        72                      1008      1080
y:  0   ┌─────┬──────────────────────┬─────┐
        │     │                      │     │
  120   │     │      内容区           │     │   有效宽 936
        │     │                      │     │
 1500   │     ├──────────────────────┤     │  ← 到这里为止
        │     │   字幕 / 平台 UI       │     │
 1920   └─────┴──────────────────────┴─────┘
```

标题统一起手位置：`x = 92, y = 200–260`。

---

## 模板 A：竖排流程（最常用）

三个节点从上往下的因果 / 数据链。适合「A 经过 B 到 C」这类讲解。

```json
{"type": "title", "text": "数据链路", "x": 92, "y": 210, "size": 88, "text_width": 352, "cue": "链路"},
{"type": "box", "text": "采集层", "x": 330, "y": 470, "w": 420, "h": 150, "r": 20, "size": 46},
{"type": "arrow", "x": 540, "y": 640, "x2": 540, "y2": 770, "head": 30},
{"type": "box", "text": "网关层", "x": 330, "y": 790, "w": 420, "h": 150, "r": 20, "size": 46},
{"type": "arrow", "x": 540, "y": 960, "x2": 540, "y2": 1090, "head": 30},
{"type": "box", "text": "平台层", "x": 330, "y": 1110, "w": 420, "h": 150, "r": 20, "size": 46}
```

节奏提示：3 个节点大约需要 **7–9 秒**配音。配音短于 7 秒就砍到 2 个节点。

## 模板 B：上下对比

讲「旧做法 vs 新做法」「错 vs 对」。两块高框上下叠。

```json
{"type": "title", "text": "两种接法", "x": 92, "y": 190, "size": 84, "text_width": 336},
{"type": "group", "text": "直连", "x": 120, "y": 420, "w": 840, "h": 330, "r": 22, "text_size": 34},
{"type": "text", "text": "PLC 直连数据库", "x": 540, "y": 540, "size": 52, "align": "center"},
{"type": "text", "text": "生产网暴露", "x": 540, "y": 630, "size": 40, "align": "center", "color": [176, 58, 48]},

{"type": "group", "text": "经过网关", "x": 120, "y": 830, "w": 840, "h": 330, "r": 22, "text_size": 34},
{"type": "text", "text": "PLC → 网关 → 数据库", "x": 540, "y": 950, "size": 48, "align": "center"},
{"type": "text", "text": "双向隔离", "x": 540, "y": 1040, "size": 40, "align": "center", "color": [13, 72, 206]}
```

`group` 是虚线框，标签自动画在框外左上角。用它做「分组 / 包围」，不占笔画预算。

## 模板 C：大数字冲击

开场 3 秒钩子用。一个数字占满一屏，冲击力最强。

```json
{"type": "text", "text": "73%", "x": 540, "y": 620, "size": 240, "align": "center", "color": [13, 72, 206]},
{"type": "text", "text": "的工业数据从未被使用", "x": 540, "y": 940, "size": 46, "align": "center"}
```

注意：数字用行楷会显示成手写体，**发出去前务必核对数字没被改**。
重大数字可以用 `"font"` 单独指定 `simhei.ttf`。

## 模板 D：并列要点

3–4 条短句逐条写下来，每条间隔 1.5 秒左右。

```json
{"type": "title", "text": "三个前提", "x": 92, "y": 210, "size": 84, "text_width": 336},
{"type": "text", "text": "一、网络分区", "x": 150, "y": 560, "size": 56, "cue": "第一"},
{"type": "text", "text": "二、单向访问", "x": 150, "y": 780, "size": 56, "cue": "第二"},
{"type": "text", "text": "三、日志留痕", "x": 150, "y": 1000, "size": 56, "cue": "第三"}
```

条与条之间留 220px 行距，不会挤。

## 模板 E：散点图 / 向量空间

讲「聚类」「相似度」「最近邻」时用。**整张散点图算一个图元**，
所以点数不会撑爆密度预算（内部点按 `stagger` 依次亮起）。

```json
{"type": "title", "text": "意义地图", "x": 92, "y": 230, "size": 84, "text_width": 350, "cue": "把每个"},
{"type": "scatter", "x": 140, "y": 560, "w": 800, "h": 560, "cue": "画到",
 "points": [
   {"dx": 0.20, "dy": 0.30, "text": "猫"},
   {"dx": 0.34, "dy": 0.18, "text": "狗"},
   {"dx": 0.18, "dy": 0.48, "text": "小猫"},
   {"dx": 0.78, "dy": 0.28, "text": "汽车"},
   {"dx": 0.88, "dy": 0.42, "text": "火车"}
 ],
 "groups": [
   {"dx": 0.25, "dy": 0.72, "text": "动物", "size": 36},
   {"dx": 0.83, "dy": 0.68, "text": "交通工具", "size": 36}
 ]}
```

`dx / dy` 是 **0..1 归一化坐标**（相对 x,y 与 w,h），不是绝对像素，原点在左下。
想让几个点「抱团」就把 dx/dy 凑近；想「隔得很远」就拉开 —— 这是表达聚类的全部技巧。
点的文字标签默认画在点上方，用 `text_dy` 可改。

**画距离连线要自己算绝对像素**：`px = x + dx*w`，`py = y + dy*h`，
然后另起一个 `line` 元素（`"dash": 18, "label": "近 = 像"`）。

## 模板 F：数据库容器 / 向量条

```json
{"type": "cylinder", "x": 120, "y": 620, "w": 380, "h": 400},
{"type": "bars", "x": 280, "y": 940, "w": 520, "h": 170,
 "values": [0.4, -0.9, 0.6, -0.2, 0.8, 0.3], "text": "[ 0.4, -0.9, 0.6, ... ]"}
```

`cylinder` 是数据库的通用简笔画（顶面椭圆 + 侧壁一笔连画）。
想在圆柱里「装东西」，再放一个 `"axes": false` 的小 `scatter` 进去 ——
视觉上是一体的，账面上是两个图元。

`bars` 表示「一串数字」，是最直白的向量形象。柱子高度取 `values` 的绝对值。

## 坐标速算

| 想要的效果 | 怎么算 |
|---|---|
| 单元素水平居中 | `x = 540 - w/2`（框）、文字用 `align: "center"` 并把 x 给 540 |
| 左右两列 | 左列 `x = 120, w = 380`；右列 `x = 580, w = 380` |
| 上下间距 | 相邻框之间留 **170–200px**（够放箭头） |
| 框中文字自动居中 | 只给 `text`，引擎按 `w/h` 居中，不用算 |
| 文字宽度估算 | 中文 ≈ 字号 × 1.0，ASCII ≈ 字号 × 0.55 |

## 图元的「画法」细节

引擎已经处理好的，写 shot.json 时不用管：

- **圆角框**：顺时针一笔画完，从左上角起笔，像人画框一样
- **箭头**：主线画完再补箭头两条斜线
- **文字**：逐字浮现（0.125 秒/字），模拟书写；字符带 ±0.5px 微抖，帧间稳定不闪
- **标题下划线**：等标题写完 60% 才落笔，且用主色
- **虚线分组框**：逐段画，每段错开 0.02 秒，形成连续感
- **散点**：先画坐标底板（0.42 秒），点再按 `stagger` 依次亮起；每个点是一笔手画的圈，
  留一个小缺口，所以看起来是「随手点的」而不是机器印的
- **圆柱**：先一笔画完顶面椭圆，再从左上起笔连画左壁 → 底弧 → 右壁
- **向量条**：每根柱子一笔画完（底 → 上 → 横 → 下），逐根错开出现；
  可选的横向基线先画

可以调的（写在元素上）：

| 字段 | 效果 |
|---|---|
| `jitter` | 抖动幅度，默认 1.15。调大更潦草，调小更工程制图 |
| `delay` | 本元素额外延后若干秒 |
| `color` | `[r,g,b]`，见 contract.md 配色表 |
| `font` | 字体覆盖：`"sans"` 黑体（**术语/缩写/数字必加**）、`"kai"` 楷体、或绝对路径 |
| `r` | 圆角半径，默认 18–20。**超过 40 就不像手绘框了** |
| `head` | 箭头个头，默认 26–30 |
| `per_char: false` | 文字整体出现，不逐字（用于很长的说明文字） |
| `text_width` | 标题下划线长度，手动给能对齐得更准 |
| `axes` | `scatter` 是否画坐标轴，默认 `true`；装进容器里时设 `false` |
| `point_r` | `scatter` 的点半径，默认 19 |
| `stagger` | `scatter` 点与点、`bars` 条与条的出现间隔（秒），默认 0.09 / 0.12 |
| `dash` / `gap` | 把 `line` / `arrow` 变虚线，用于「距离 / 相似度」这类非实体连接 |
| `label` | `line` 的中点标签，如 `"近 = 像"`；配 `label_color`、`text_size` |
| `dur_scale` | 本元素整体绘制速度缩放，`< 1` 更快。复合作图笔画多时用它压时长 |

> **含拉丁字母的元素一定要给 `font: "sans"`。** 行楷下 `AI` 会长得像 `A7`、
> `PLC` 的 L 会连成一笔。这是本方案唯一的"必须破格"的地方 —— 手写感可以牺牲一个元素，
> 可读性不能牺牲。
